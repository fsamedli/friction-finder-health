# Friction Finder demo script (v0.10, Lanford Health, Oct 27, 2026)

**Five steps in 5 to 7 minutes**, the order Prof. Hall suggested on Oct 21 (problem and money → investigate with
the questions → plan and edit → checklist → review and worth). The time limit is **not confirmed**: the team
expected five to seven minutes; confirm it with Prof. Hall and cut step 5's optional Business case click if it is
five. Timings below are rehearsal targets, not measurements, except where a measured time is given. Every figure in
the "Say" column was read from the API on Oct 27, 2026 (keyless); say them from the screen, not from memory. The
guided demo (top bar → **Start demo**) walks the same five steps with one sentence of narration each and no model
call. Lanford Health, its three hospitals and all data are fictional and synthetic; operating records are
unit-level counts, never patient data.

## Before you go on stage (5 minutes before)
1. `./scripts/demo_check.sh` must end with `… passed, 0 failed` (keyless, 1440 and 390 px, private port 8020;
   356 passed, 0 failed on Oct 27). If not, use the fallback laptop.
2. `cd web && npm run build` if you pulled new code (`run_demo.sh` only builds when `web/dist` is missing), then
   `./run_demo.sh` (port 8001), user menu → **Reset demo**, demo clock reads **Sept 15**, hospital **Lanford**,
   role **Nurse manager**.
3. Browser zoom **100%** (⌘0). Close other tabs. Notifications off. Have the one-page report's print dialog
   tested once (⌘P → Save as PDF) so step 4 does not stall.
4. Decide keyed or keyless. Keyless (`env GW_AZURE_OPENAI_KEY= OPENAI_API_KEY= ./run_demo.sh`) answers in under a
   second and labels itself "rules mode, no model"; the owner notices read "Templated · rules mode". With the GW key,
   a typed question took 18 to 58 s per turn on the v0.8 data (ten live turns, Oct 8; not yet measured on the
   hospital data) and the notices are rewritten by the model in the background and swapped in only if the check
   passes. Prepared answers for this variant are generated by `scripts/prepare_investigations.py`; until that is
   re-run, chip questions run live or in rules mode.

**Q&A only, one click away:**
- **Trust & method › Architecture:** the agentic answer (paragraph plus the three-row table), the loop, the tool
  registry, the budgets (6 checks, 8 model calls, 60 s), where the model is used.
- **Trust & method › Quality:** gold 13/13 in rules mode (first run 11/12 on Sept 17), adversarial 15/15 (first
  run 10/15), investigation pack 16/16 (first run 11/16); with gpt-5-mini gold 12/12 and adversarial 15/15 on Sept
  24, investigation 15/16 on its Oct 8 first run. "Approvals are never evidence that an answer was correct."
- **Trust & method › Assumptions:** minimum n 4; 311 responses; follow-up months synthetic; the external benchmark
  unavailable; the two-month pulse assumed (F wave 2 adds the Gallup quartile gap, the 300-staff scenario and the
  pricing note).
- **Action plans:** the board with the Checklist column, the queues, and (D wave 2) the plan that needed revision
  next to the one that worked.
- **Data sources:** every source is a synthetic CSV (survey export, eMAR export, timekeeping, HRIS, employee
  health log, procedures); in a pilot the hospital uploads its own team-month file. No patient-level data.
- **/ask** (top bar **Ask**): the panel full width; `/ask?view=brief` keeps the v0.7 one-page brief.

## What breaks first, and the fallback

| Step | Mode | Latency | What breaks first | Fallback |
|---|---|---|---|---|
| Today, Investigate blocks, Plans, Checklist, Review | code only | under 1 s (no model call) | the server dies | `./run_demo.sh` in a second terminal (seconds once `web/dist` exists) |
| Panel question (key present) | model chooses checks; code computes; model words the answer, then code checks it | 17.6 to 57.8 s per turn on the v0.8 data (Oct 8); not yet measured on the hospital data | **model latency or GW Azure down** | the app falls back to the fixed plan by itself and says so; for a predictable demo run keyless (rules mode, under a second, labelled) |
| Panel, prepared answer | model run saved earlier, labelled | instant | a question that is not one of the saved turns runs live; **no prepared answers exist for this variant until `scripts/prepare_investigations.py` is re-run** | the scripted turns, in order, with the team context Med-Surg Night on Sept 15: "Why is Med-Surg Night flagged?" → "Could staffing explain this?"; "Compare it with the other night shifts" → "When did it start?"; "Is this normal for teams like ours?" → "What is missing?" |
| Approve plan | code | under 1 s | a double click | blocked: one `request_id` per draft; a repeat returns the saved plan with an explanation |
| Owner notices (key present) | templated at approval; the model rewrites in a background thread; swapped in only if the check passes | approval never waits; the page polls while "drafting" | the model invents a date, number or name | the check rejects it (owners must match the plan, every number must be in the plan, under 140 words, no causal claim); two failures and the templated notices stay, labelled |
| Checklist tick, edit, add | code | under 1 s | a stale page after another tab changed the plan | reload; every change is on the server and in `approvals.jsonl` with the time |
| One-page report as PDF | browser print | seconds | pop-up blocked | **Download** link on the Review page, or open `/api/report/<plan id>` directly |

Other fallbacks:

| Problem | Do this |
|---|---|
| The laptop dies | Fallback laptop, cloned and checked the same morning with `scripts/demo_check.sh`. Last resort: the Oct 27 screenshots in `docs/overnight/v0.10/_verify/` (judges penalise screenshots; only if everything else fails) |
| A plan was approved in rehearsal | User menu → **Reset demo** (removes live plans, ticks and edited unit costs) |
| Wrong date showing | Top bar → demo clock → Sept 15 |
| Wrong hospital or role | Top bar → **Lanford**; user menu → **Nurse manager** |
